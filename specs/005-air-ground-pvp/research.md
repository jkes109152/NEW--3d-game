# PvP 研究與決策

日期：2026-09-08。此文件是設計研究，尚無 PvP 執行驗收結果。

## 一、沿用現有技術與服務

- **決策**：保留既有 Python 純規則、Pyodide、Three.js、React、vinext 與 Sites D1；不安裝新引擎、不新增 WebSocket 或外部服務。
- **理由**：使用者最後改回房主判定；現有 `web/lib/game.ts` 已載入 Python 並使用同一多人名稱服務。功能焦點是 PvP，無需遷移合作模式。
- **排除方案**：獨立伺服器判定與 Durable Objects 超出最後選擇；把 AI 敵機換外觀仍不能提供真人飛行。
- **依據**：`web/package.json`、`web/pnpm-lock.yaml`、`web/.openai/hosting.json`、`web/lib/game.ts`。

## 二、獨立純規則與呈現

- **決策**：新增 `air_defense/pvp.py` 組合 V3、鎖定及基礎武器資料，獨立管理角色與當局；不繼承帶有城市、空降兵、成長及存檔副作用的 BattleState。另以 `pvp_motion.py` 管理可由權威與預測共用的移動／碰撞純函式。
- **理由**：`air_defense/state.py` 與 `multiplayer.py` 共享合作世界，直接修改容易引入 PvP 獎勵或 AI 副作用。重用無副作用幾何與鎖定，不重用完整戰役狀態。
- **排除方案**：在 Three.js 重寫命中規則會形成第二真相來源；將一般玩家存檔傳入 PvP 無法保證基礎配裝。
- **決策**：`web/public/bridge.py` 新增 PvP 專用入口，`web/lib/pvp-session.ts` 管理生命週期；`pvp-scene.ts` 管理場景，不啟動第二份多人輪詢。切入 PvP 時暫停既有場景繪製並隱藏其 HUD，離開後恢復。

## 三、固定飛行、戰區與碰撞

- **決策**：規則沿用 x 向右、y 向上、z 向前；渲染用既有 z 反號轉換。固定 1/120 秒步進，時間與亂數可注入；截止時間截短最後一步，先處理期間命中再判時間。
- **決策**：依 spec 固定速度 24–55、初速 40、加速度 12、偏航每秒 120 度、俯仰每秒 90 度且正負 70 度、翻滾每秒 180 度。Q／E 改變機身滾轉與相機水平線，不把偏航／俯仰軸跟著旋轉，也不提供無敵；採街機式操控。
- **決策**：地面 x、z 限制於正負 99.55，重力每秒平方 18 公尺，碰撞半徑 0.45、高度 1.8、視點離地 1.6。地面移動遇到障礙時分軸滑動，不穿牆。
- **決策**：四座障礙盒的中心／全尺寸分別為 (-45,6,-25)/(10,12,18)、(45,6,25)/(10,12,18)、(-25,4,45)/(16,8,10)、(25,4,-45)/(16,8,10)。美術圓角外觀必須對齊可見碰撞體，禁止加入隱形牆。
- **決策**：地面出生 x=-12、-4、4、12，y=0、z=0，朝向 z 正向。空中出生 x=-30、-10、10、30，y=40、z=70，朝向 z 負向，按各隊名單索引取前 N 點；互相不碰撞。
- **決策**：飛機碰撞採中心半徑 1.5 的球，障礙以擴張盒做掃掠，地面接觸 y=1.5 即撞毀。水平與高度越界依中心判定；回到合法範圍重置五秒連續越界倒數。
- **決策**：導彈使用既有速度、壽命、240 度轉速及 1.5 公尺命中距離；追蹤方向按三維限角旋轉，位置只沿朝向前進。以相對運動掃掠檢查飛機與導彈前後位置，避免低畫面更新率穿透；目標已淘汰則導彈失效。不新增與既有基礎導彈不一致的障礙傷害行為。
- **決策**：取得框仍為螢幕高度 21%；以地面相機的垂直視角 65 度與畫面比例計算同一投影，視線障礙判定使用 PvP 戰區。不得直接使用 `target_in_box` 的水平 FOV 預設造成準心與可鎖定範圍不一致。
- **排除方案**：停滯／失速、真實飛行動力、碰撞友軍與地面撞擊傷害均非需求；無限追趕與直接瞬移破壞可躲避性。

## 四、操作與預測

- **決策**：滑鼠位移映射成累積期望偏航／俯仰量，每像素 0.12 度乘靈敏度；消耗量由固定步轉向上限限制。鍵盤方向鍵輸入歸一化轉向軸，反轉設定只反轉俯仰。W／S 與 Q／E 相反鍵同按相抵。
- **決策**：`pvp-controls.ts` 處理按住狀態、有限數字、指標鎖定、快捷鍵與偏好，設定或失焦時清空未消耗輸入並要求重新按下射擊；飛機維持現有速度朝向，不自動拉回。
- **決策**：非房主透過同一 Python 移動函式預測自己的角色，保留最多 1 秒未確認操作；收到帶確認序號的權威狀態後回放剩餘操作，視覺偏差在 100 毫秒內收斂，大於 10 公尺則立即校正。預測不計算傷害、鎖定完成、淘汰或勝負。
- **決策**：其他角色使用最近兩份快照插值，最多外推 200 毫秒；更久則凍結呈現並顯示連線狀態，不能假造命中。HTTP 輪詢沿用現有戰鬥請求完成後 120 毫秒排程，最多一個請求在途。
- **依據**：現有 `multiplayer-client.ts` 已有串行請求、累積視角與可靠命令；目前合作預測僅修正視角，需要獨立 PvP 移動回放。

## 五、研究完成界線

所有玩法與技術選擇均在本文件及契約固定；網路延遲和可躲避性仍需依 quickstart 實測，不以研究通過代替效能證據。若不能達成 spec，修正程式；涉及數值變動必須先更新規格與決策，不能默默放寬成功標準。

## 六、房間與同步研究結果

本節納入唯讀研究代理對 `multiplayer-server.ts`、`multiplayer-client.ts`、`game.ts` 與 `db/schema.ts` 的檢查，沒有代理修改程式。

- **決策**：保留合作 MAX_PLAYERS=4 與倍率函式；以 mode 推導 PvP 容量 8。PvP ready 不要求 profile，finish 不寫 mp_results，again 不計算下一關。
- **理由**：原常數同時控制加入、快照上限及合作獎勵；直接改為 8 或產生零元收據仍會改變合作與存檔契約。
- **決策**：新增 countdown、starts_at、time_limit_seconds、host_instance_id、simulation_seen_at、result；伺服器 start 隨機分隊並保存當局名單。成員新增 input_stream、input_instance、departed_at，配合 resume 的版本比較換代。
- **決策**：輸入一秒未更新即停用，非房主十秒未連線即永久退出當局。倒數期間一秒無成員更新就取消開局。開始倒數後輪詢改為戰鬥頻率，不使用等待室 800 毫秒排程。
- **決策**：房主 simulation instance 每次頁面載入新建，不放入可跨重載保存的位置；與開局已保存值不同就中止，即使尚未發布第一份快照也相同。
- **決策**：房主正常畫格依實際經過時間補固定步，不使用原本每幀 0.06 秒截斷。最多補 120 步；落後超過一秒、補步無法完成或 Python 發生例外則主動 abort。伺服器十秒未收到新的 simulation tick 即中止；普通請求不能續租模擬健康。
- **決策**：每個操作都驗證 runId，input 的序號與命令確認以 runId、playerId、伺服器核發 inputStream 為作用域；新分頁以 resume 換代後，舊 stream 不得自動再次取得作用權。
- **決策**：快照保存完整狀態；128 項事件環只做聲光回饋，不能成為傷害、淘汰或結算的唯一依據。末局結果持久化於房間，abort 與 finish 皆需條件式寫入、先查超時與房主有效性。
- **排除方案**：只看 online 布林無法分辨一秒停用／十秒退出；沿用房主暫停或 sequence>0 重載判斷有漏洞；改用 WebSocket 超出本版服務範圍。


## 七、設計複核修正

唯讀研究複核發現並已處理三項缺口：以 sync 初始化查詢解決非房主首次開局／重載沒有 runId 或串流的循環依賴；finish 驗證補上空中存活必須已到時限；取消操作同步前移確認水位，避免恢復時補做舊轉向／射擊。多人契約與對應任務已同步補齊，沒有將這些選擇留給實作。
